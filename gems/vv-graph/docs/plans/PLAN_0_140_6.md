# PLAN_0_140_6 — server-side JSON-LD projection (v0.1 + v0.2)

## v0.2 addition (2026-06-07): persistence shipped

The Bindable shape from v0.1 is now wrapped in an
engine-shaped persister. `Harness::HyperSource::Persister.publish(path)`
emits `INSERT DATA { ... }` via
`Vv::Graph::Sparql.execute(query, graph: 'urn:mm:hypersource')`,
putting the FileMetadata triples into the queryable named graph.
A `hypersource_publish` MCB action exposes the persister so the
operator (or future auto-projection hook) can publish on demand.
Existing sparql_query then reads via `SELECT ... WHERE ... GRAPH
<urn:mm:hypersource> { ... }`. Retention (PLAN_0_140_9) defers.

> Status: **shipped**. Sixth slice of the 0.140 HyperSource
> family. v0.1 ships the RDF projection SHAPE — the Turtle
> serialisation HyperSource metadata projects into. Persistence
> + SPARQL writer ship as a v0.2 wiring slice once the
> Vv::Graph::Sparql write-side API is confirmed.

## Module design follows the biological model

The projection module is **Bindable-shaped**: pure stateless
function from a workspace path to a Turtle string. No AR access
(the projection delegates to MetadataProjection from
PLAN_0_140_3), no Vv::Graph dependency, no I/O. v0.2 will wrap
this Bindable in an engine-shaped persistence layer; the shape
locks first.

## What ships

- `Harness::HyperSource::GraphProjection`:
  - `GRAPH_IRI = 'urn:mm:hypersource'`
  - `VOCAB_IRI = 'urn:mm:vocab/'` (placeholder)
  - `iri_for(path)` — stable file IRI.
  - `triples_for(path)` — Turtle string for the path's metadata.
- Spec coverage for the Turtle shape.

## What does NOT ship

- Persistence into a named graph.
- MCB action for on-demand publication.
- Auto-projection from fs_write / fs_edit.
- Retention / GC.
- Full JSON-LD @context document.
