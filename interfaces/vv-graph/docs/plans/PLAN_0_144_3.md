# PLAN_0_144_3 — gem inventory + alignment_score_all

Status: Active
Parent: [PLAN_0_144_0](PLAN_0_144_0.md)
Predecessors: [PLAN_0_144_1](PLAN_0_144_1.md), [PLAN_0_144_2](PLAN_0_144_2.md)
Date: 2026-06-07

## Slice intent

Third slice of the alignment family. Makes the Scorer's output
honest by feeding it canonical per-gem paths from a versioned
inventory file.

Three pieces:

1. `docs/architecture/gem-inventory.yaml` — canonical YAML
   inventory: slug, IRI, language, library/engine/presentation
   paths, action glob, version.
2. `Harness::Alignment::Inventory` — service that loads + queries
   the YAML; exposes `.list` / `.find(slug)` / `.actions_for(slug)`.
3. Two new MCB actions:
   - `gem_inventory_list` — read-only list surface.
   - `alignment_score_all` — runs alignment_score across every
     inventory entry, returns aggregate `L_alignment_total`.

## Why YAML, not Turtle (yet)

The direction notes both options. v0.1 picks YAML for editability +
zero-dep parsing. v0.2 (144_3b) can switch to Turtle when the
`urn:mm:alignment` graph gains persistence and inventory entries
should be SPARQL-queryable. The shape is identical; only the on-
disk format changes.

## Inventory entry shape

```yaml
vv-graph:
  iri:          urn:mm:gem:vv-graph
  language:     ruby
  root:         vendor/vv-graph
  library:      vendor/vv-graph/lib
  engine:       null              # vv-graph has no engine layer today
  presentation: null              # nor a presentation layer
  action_glob:  null              # vv-graph doesn't register MCB actions
  version_path: vendor/vv-graph/VERSION
```

`library` / `engine` / `presentation`: `null` when the layer is
absent (the Scorer's P1 will reflect this honestly).

`action_glob`: a `Dir.glob` pattern resolving to action source
files for P2/P3/P4. `null` means no actions to grade.

`version_path`: optional pointer to a VERSION file or similar so
the inventory carries the gem version without duplicating it.

## v0.1 seed inventory

Covers the gems whose alignment is meaningfully scorable today:

- vv-graph (Ruby RDF/SPARQL primitive)
- vv-memory (Ruby memory tier)
- vv-mcb (Ruby MCB framework)
- vv-multiplayer (Rust multiplayer engine)
- mm-cli (Rust CLI)
- mm-wt (Rust WebTransport sidecar)
- mm-supervisor (Rust out-of-band supervisor)

## Inventory API

```ruby
Harness::Alignment::Inventory.list                  # → [Hash, …] sorted by slug
Harness::Alignment::Inventory.find("vv-graph")      # → Hash or nil
Harness::Alignment::Inventory.actions_for("vv-graph") # → [path, …] via Dir.glob
Harness::Alignment::Inventory.paths_for("vv-graph") # → { library:, engine:, presentation: }
Harness::Alignment::Inventory.path                  # → docs/architecture/gem-inventory.yaml
```

Stateless; reloads the YAML on each call so `bin/mm-folder-cache`-
style invalidation isn't needed. v0.2 may cache with mtime check.

## MCB actions

### gem_inventory_list

```
gem_inventory_list()
  → {
      ok:    true,
      count: 7,
      gems:  [ { slug, iri, language, root, library, engine,
                 presentation, action_glob, version_path }, … ]
    }
```

Read-only; actor: :none.

### alignment_score_all

```
alignment_score_all(slugs?: ["vv-graph", …])  # optional filter
  → {
      ok:                  true,
      count:               7,
      per_gem:             [ { gem, l_alignment, composite_score,
                               p1:, …, p7: }, … ],
      l_alignment_total:   0.49,
      checked_at:          "..."
    }
```

Iterates the inventory, calls `Scorer.score` per gem with the
inventory's `paths_for` + `actions_for`, aggregates the mean of
`l_alignment` into `l_alignment_total`. Optional `slugs:` filter.

Read-only; actor: :none.
