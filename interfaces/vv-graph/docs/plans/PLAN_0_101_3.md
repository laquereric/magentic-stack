# PLAN_0_101_3 — graph:review:ingest rake task (slice 3 of PLAN_0_101_0)

> Slice 3 of [PLAN_0_101_0](PLAN_0_101_0.md). The
> events→N-Quads projector; slice 4's MCB action queries
> what this slice writes.

## What landed

`server/lib/tasks/graph.rake` gains a new `graph:review` namespace
with one task: `graph:review:ingest`. It reads
`tmp/planrunner/events.jsonl`, finds events past
`tmp/graph/reviews.hwm`, and projects them into
`tmp/graph/reviews.nq` as N-Quads scoped to per-review named
graphs (`urn:mm:review:<id>`).

## Why N-Quads (not Turtle)

The existing `graph:extract` already emits N-Quads to
`tmp/graph/*.nq`, and PLAN_0_99_3 standardised per-branch named
graphs via the 4th term. Reviews join that convention: each
review gets its own named graph URI as the 4th term, so a query
can scope to one review without ambiguity. Turtle has no
named-graph syntax; .nq is the right output format.

## Citation validation

Each cited `PLAN_X_Y_Z` from the event is checked against the
filename set under `docs/plans/`. Unresolved cites:

- Are **dropped** from the projected triples (no phantom
  `mm:cites <urn:mm:plan:PLAN_X_Y_Z>` edges).
- Are **warn-logged** to stderr as
  `ReviewCitationUnresolved review=<id> plan=<pid>`.

Wrong-direction prevention: if we projected unresolved cites,
the graph would silently grow phantom plan nodes and a SPARQL
`SELECT ?p WHERE { ?r mm:cites ?p }` would return things that
don't exist as plans. The drop-with-warning shape matches how
the substrate handles other typed-reference failures.

## Idempotency mechanism

`tmp/graph/reviews.hwm` holds a single integer: the byte offset
into `events.jsonl` past which we've already projected. Each
run seeks past hwm, processes only new bytes, and writes the
new hwm at the end. If events.jsonl shrinks (rotation, manual
truncate), hwm resets to 0 and the whole file is re-projected;
Oxigraph's set semantics deduplicate on load, so this is
correctness-safe (just a little wasted I/O).

## What's deliberately NOT in this slice

- **Auto-wiring into graph:server:reload.** Operator runs
  `graph:review:ingest` explicitly. Auto-wiring is a slice 6
  follow-up after the parser is proven.
- **SHACL validation pass.** review_shape.ttl from slice 1 is
  on disk but not yet wired into the validation pipeline; that
  follow-up is broader than this milestone.
- **Per-candidate promotion tracking.** When the operator turns
  a candidate into a real PLAN file, mm:candidateStatus stays
  "unpromoted" until slice 5 (or a small follow-up) wires the
  promotion detection.
