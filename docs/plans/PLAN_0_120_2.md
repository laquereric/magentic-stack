# PLAN_0_120_2 — Closed substrate, open doctrine

> Status: **draft (doctrine)**. Parent: PLAN_0_120_0. Continues
> the doctrine family from PLAN_0_120_1 (hosted-only +
> Rails-idiom-not-internals) with the third invariant: which
> artifacts publish publicly, which stay closed, and why.

## The publish-test (one screen)

Three criteria, all must hold for publish:

| Criterion | Test | Source |
|---|---|---|
| **Does NOT compound with MM-specific use** | Is the artifact's value the same on day 1 and day 1000 of use? Sandbox runtimes, SPARQL tools, protocol specs all pass. Memory stores, projection pipelines, agent loops fail. | [AnthropicSandboxes.md](../research/AnthropicSandboxes.md) compounding test |
| **Lives in L1 (Constraint) or L3 (Execution)** | Protocol surfaces (L1) and tool/sandbox surfaces (L3) publish. Context (L2), Verification (L4), Lifecycle (L5) do not. | [AnthropicSandboxes.md](../research/AnthropicSandboxes.md) 5-layer harness |
| **Is substrate-decoupled** | A fresh `git clone` of the candidate, `bundle install`, run its specs — succeeds in isolation. No import of `vv-memory`, `vv-medallion`, `vv-mcb` internals, etc. | ClosedSource.md ref [20] (don't accidentally open-source via licensing) |

All three yes → **publish.**  Any one no → **keep.**

## Worked examples — first two publications

### sqlite-sparql ✓ publish

- **Compounding test**: SPARQL queries run the same on day 1 and day 1000. PASS.
- **Harness layer**: L3 Execution (a tool the substrate uses). PASS.
- **Substrate decoupling**: Already substrate-load-bearing inside MM, but the artifact itself is a clean Oxigraph wrapper — no `Vv::Memory` imports. Smoke-extract pass to verify.

### other/json-rpc-ld ✓ publish

- **Compounding test**: A protocol spec doesn't get richer with MM-specific use. PASS.
- **Harness layer**: L1 Constraint (a protocol). PASS.
- **Substrate decoupling**: Currently unused inside MM (`git grep` clean). PASS trivially.
- **Bonus**: standards-track aspiration — open publication invites broader linked-data community adoption; MM gets positioning credit similar to Anthropic + MCP.

## The non-publish list (worked examples — kept)

| Artifact | Why kept |
|---|---|
| **vv-memory** | L2 Context. Storage + tier projections compound monotonically with use. |
| **vv-medallion** (PLAN_0_124_0) | L2 Context. CQRS projection plane; Conformer + Curator implementations. The compounding moat itself. |
| **vv-mcb internals** | L4 / L5. The MCB action surface + the ActorGate + the audit framework all compound with operator usage; their value grows with every MCB call. |
| **vv-process** (specifics beyond the public DSL) | L5 Lifecycle. Step machinery + retry-and-resume + audit trail compound with every flow that runs through them. |
| **planrunner-* family** | L5 Lifecycle. Event log + executor + intake compound with substrate usage. |
| **The substrate's runtime + customer data + apps deployed on MM** | This is the moat per PLAN_0_120_1 hosted-only doctrine. Closed by infrastructure, not by license. |

## The Anthropic precedent

Anthropic open-sourced MCP (the protocol surface) → it became
the de facto agent-tool interface. They kept the agent loop +
context + memory + dreaming + outcomes grader closed because
those compound with customer use.

**MM's structure is identical:**

- **MM's MCP equivalent** = the eventual MCB protocol spec, plus
  json-rpc-ld as the underlying envelope shape. **Publish.**
- **MM's agent loop equivalent** = vv-process + vv-medallion's
  Flow dispatch. **Keep.**
- **MM's memory equivalent** = vv-memory + vv-medallion's
  Conformer + Curator projections. **Keep.**

Open the protocol. Close the loop. Same pattern, same line,
same logic.

## The test every future gem proposal has to pass

When `git add vendor/vv-newthing` lands in a PR, the PR's review
checklist includes:

1. **Compounding test** — does this artifact get richer with
   MM-specific use? If yes → keep. If no → continue.
2. **Harness layer** — what L1/L2/L3/L4/L5 layer does this sit
   on? L1/L3 → publish-eligible. Otherwise → keep.
3. **Substrate coupling** — fresh clone + bundle install + spec
   run succeeds in isolation?
4. **PUBLISH_CHECKLIST.md present** in the gem with the answers
   recorded (even if the answer is "keep" with a one-line reason).

The doctrine doesn't add overhead — it gives the operator + future
hires a *defensible* answer to "why is this open / closed?" in
about 30 seconds of reading.

## Irreversibility

Publishing is one-way. The public history can't be retracted;
forks exist the moment the repo is starred; the community is
alienated by un-publishing. Apply the test conservatively. **When
in doubt, KEEP.** A later publish is cheap; a later un-publish is
catastrophic.
