# PLAN 0.12.1 — Ontology Alignment: Triple Predicates to Schema.org

## The Gap

The triple store uses custom `mm:` predicates (`mm:category`, `mm:name`, `mm:brand`). The Knowledge Research document requires Schema.org alignment for interoperability with the agentic commerce protocol stack (MCP, UCP, ACP). Products use internal SKUs (`EPET2850`) instead of globally interoperable GTINs.

```
Current:                              Target:
mm:category → "printer"               schema:category → "printer"
mm:name → "Epson EcoTank ET-2850"     schema:name → "Epson EcoTank ET-2850"
mm:brand → "Epson"                    schema:brand → "Epson"
(none)                                schema:gtin → "0010343965089"
(none)                                schema:offers → {priceCurrency, price, availability}
```

This is a rename + extend, not a restructure. The Triple model (`server/packs/platform/app/models/triple.rb`) stores predicates as strings. ProductTripler (`server/packs/partner_bhphoto/app/services/product_tripler.rb`) emits triples with `mm:` namespace. Seeds (`server/db/seeds.rb`) use `mm:category`, `mm:name`, `mm:brand`.

## What Changes

### 1. Predicate Rename

| Current | Schema.org | Notes |
|---|---|---|
| `mm:category` | `schema:category` | Direct rename |
| `mm:name` | `schema:name` | Direct rename |
| `mm:brand` | `schema:brand` | Direct rename |
| `priceCents` | `schema:offers` | Restructure: `{priceCurrency: "USD", price: 279.99, availability: "InStock"}` |
| `rdf:type` | `rdf:type` | Already standard — no change |
| `inFolder` | `inFolder` | Internal navigation — no change |
| `mm:<spec>` | `mm:<spec>` | Product specs stay custom until ontology derivation (Phase 2) |

The `schema:` prefix maps to `https://schema.org/`. ProductTripler's namespace constant changes:

```ruby
# Before
MM = "https://magenticmarket.ai/vocab#"

# After — add Schema.org namespace alongside MM for custom predicates
SCHEMA = "https://schema.org/"
MM = "https://magenticmarket.ai/vocab#"
```

### 2. GTIN Field on Product

Add `gtin` string field to the Product model. For the B&H Photo partner pack, GTINs are optional — many products won't have them initially. The field enables future cross-domain anchoring without requiring it now.

```ruby
# Migration
add_column :products, :gtin, :string
add_index :products, :gtin, unique: true, where: "gtin IS NOT NULL"
```

ProductTripler emits `schema:gtin` when the product has one:

```ruby
def index_product!(product)
  uri = product_uri(product)
  Triple.assert!(subject: uri, predicate: "schema:name", object: product.name, ...)
  Triple.assert!(subject: uri, predicate: "schema:brand", object: product.brand, ...)
  Triple.assert!(subject: uri, predicate: "schema:category", object: product.category, ...)
  Triple.assert!(subject: uri, predicate: "schema:gtin", object: product.gtin, ...) if product.gtin.present?
end
```

### 3. Schema:offers Predicate

The current `priceCents` integer triple becomes a `schema:offers` triple with structured object data. The Triple model already supports `object_type: :literal` with arbitrary string values. Store the offer as JSON-LD shaped data:

```ruby
Triple.assert!(
  subject: uri,
  predicate: "schema:offers",
  object: { priceCurrency: "USD", price: product.price_cents / 100.0, availability: product.in_stock ? "InStock" : "OutOfStock" }.to_json,
  object_type: :literal,
  provenance: :EXTRACTED,
  confidence: 1.0
)
```

### 4. to_jsonld Alignment

Context records already have `to_jsonld`. Update the JSON-LD output to use Schema.org/Product shape when the context references a product:

```ruby
def to_schema_product
  {
    "@context" => "https://schema.org",
    "@type" => "Product",
    "name" => payload["name"],
    "brand" => { "@type" => "Brand", "name" => payload["brand"] },
    "category" => payload["category"],
    "gtin" => payload["gtin"],
    "offers" => {
      "@type" => "Offer",
      "priceCurrency" => "USD",
      "price" => payload["price_cents"]&.to_f&./(100),
      "availability" => "https://schema.org/InStock"
    }
  }.compact
end
```

### 5. OntologyResolver Consumers

OntologyResolver doesn't query triples by predicate directly — it uses OntologySynonym records. But `seed!` reads Triple data to build the synonym table. Update the seed query:

```ruby
# In OntologyResolver.seed!
# Before
categories = Triple.where(predicate: "mm:category").pluck(:object).uniq
# After
categories = Triple.where(predicate: "schema:category").pluck(:object).uniq
```

### 6. Downstream Predicate References

Search all code that references `mm:category`, `mm:name`, `mm:brand`, or `priceCents` and update to Schema.org equivalents.

Known locations:
- `server/db/seeds.rb` — triple seeding
- `server/packs/partner_bhphoto/app/services/product_tripler.rb` — triple creation
- `server/packs/platform/app/services/ontology_resolver.rb` — seed! method
- `server/packs/marketplace/app/services/query_first_responder.rb` — triple queries
- Any spec files referencing these predicates

## What NOT to Change

| Item | Why |
|---|---|
| Custom `mm:<spec>` predicates (inkSystem, hasFeature) | Product specs don't map cleanly to Schema.org until LLM-derived ontology (Phase 2) |
| `rdf:type`, `inFolder` predicates | Already standard or internal-only |
| OntologyResolver classification logic | Stem/fuzzy/vector tiers work — LLM fallback is Phase 2 |
| Triple model schema | No structural change — predicates are strings |
