# PLAN_0_159_18 — User Journey graph on the home page

**Strategy:** AlphaSplash.
**Status:** draft.

## Why

Operator (2026-06-10): the home page today expresses three things —
(a) MM can be many things, (b) MM wants to help the way the user
wants help, (c) MM adapts to the user. The next step is for MM to
**make explicit what it just learned** from the user, and lean into
**Cognitive Assistance (CA)** as the differentiator. Users assemble
a personalised toolbox; they see it; they can change it any time.

Concretely: every CTA on the home page populates a **User Journey
graph**. The home page **assembles** before any User Flow runs. Once
the Journey is non-empty, a single Continue button kicks off the
flow (today: the chat-prompt page seeded with the assembled
personas + question).

Personas are **fluid** — add and drop any time. The horizontal
sliding floating-words bar already expresses that; chips slide the
same way.

Perspective shift example:

  Before: "Pick your MM persona"
  After:  "Add a MM Persona"

## What ships

### `vendor/vv-web/src/journey.js` (new)

`VvJourney` mirrors the shape of `VvGamer` / `VvTheme`:

- State: ordered list of `{kind, id, label}` where `kind` is
  `'path' | 'persona' | 'question'`. Deduplicated by `(kind, id)`.
- Persisted to `localStorage` under `mm.journey.v1` (versioned so a
  schema change can be migrated cleanly later).
- API: `add(item)`, `remove(kind, id)`, `clear()`, `onChange(fn)`,
  `items` (getter).
- `mountBar(parent)` renders the chip strip (empty placeholder when
  no items) and a Continue button (hidden when empty).

### `vendor/vv-web/src/splash.js`

- Instantiate `VvJourney`, mount the bar below the header and above
  `.mm-main`.
- Pass `journey` to `VvObjectivePath` and `mountFloatingWords`.
- Chat submit becomes `journey.add({kind:'question', id:'q1', label:q})`
  instead of `navigateToChatPrompt(q)`.
- Continue button URL: `#chat-prompt?personas=A,B&q=Q1&q=Q2`
  (multi-persona, multi-question). Single legacy params still
  accepted by chat-prompt.js (already does `?persona=` / `?q=`).

### `vendor/vv-web/src/objective-path.js`

- Card click → `journey.add({kind:'path', id, label})`. Card paints
  `✓ Added` state when item is in journey. Removing the chip restores
  the card.
- Copy: section heading "Pick your MM persona" → "Add a MM persona".
  Per-card CTA text changes to "Add".

### `vendor/vv-web/src/floating-words.js`

- Word click → `journey.add({kind:'persona', id:word, label:word})`.
  Persists like path-card adds.

### `vendor/vv-web/src/styles.css`

- `.mm-journey-bar` — horizontal sliding row matching floating-word
  visual grammar.
- `.mm-journey-chip` (per-kind tints), `.mm-journey-chip-remove`
  (× button), `.mm-journey-empty` (placeholder copy),
  `.mm-journey-continue`, `.mm-journey-clear`.

### `server/app/controllers/mcb_manifest_controller.rb`

- Read `params[:personas]` (comma-joined) and `params[:intents]`.
- Emit one `UserJourney` record listing all added items.
- Emit one `Persona` record per persona (was: only one).
- Single `?persona=` / `?q=` still works (single-element list).
