Third per-gem alignment slice. Lift P5 (graph projection) from
0 → 1 for **all 7 inventoried gems** + extend the Scorer's P5

rather than `graph_projection.rb` only).


## Why `graph_projection.md` (not `.rb` / `.rs`)

The doctrine [P5](../architecture/principles/biological-interface-gem.md#p5--graph-projection-the-cell-secretes-signal)
requires the gem to own its named graph projection. The current
Scorer heuristic checks for `library/<gem>/graph_projection.rb`
— Ruby-specific.

For a polyglot substrate (Ruby + Rust today; Python / Elixir /
Swift later), the projection declaration shouldn't be tied to
the gem's *implementation* language. The declaration is the
**contract** ("this gem owns urn:mm:<slug> with these
predicates"); the implementation is whatever runs inside the
gem.

So this slice:

1. Updates the Scorer to accept `graph_projection.*` (any
   extension), then
2. Ships `graph_projection.md` declarations — markdown documents
   that name the IRI + predicate set, free of language
   dependency.

A gem that later wires a real Ruby `graph_projection.rb` can
co-exist with its `.md` declaration; the Scorer accepts either.
The `.md` becomes the durable contract document; the `.rb`
becomes the live implementation.

## Scorer change

```ruby
# Before:
proj = ::File.join(paths[:library], "graph_projection.rb")
return { score: 1.0, evidence: proj } if ::File.file?(proj)

# After:
proj_glob = ::File.join(paths[:library], "graph_projection.*")
proj_files = ::Dir.glob(proj_glob)
return { score: 1.0, evidence: proj_files.first } if proj_files.any?
```

Falls back to the existing action-source-scanning if no
declaration file is present (unchanged behaviour for gems that
project via direct `Vv::Graph::Sparql.execute` references).

## Per-gem projection declarations

Each gem gets a `graph_projection.md` declaring:

- Owned named graph IRI (`urn:mm:<short-slug>`)
- Predicate vocabulary the gem emits
- Read/write boundary (who's allowed to write triples vs read
  via SPARQL)
- Implementation status (declarative-only / wired)

The content is short (15–40 lines) and follows the same shape
as the routing/hypersource/health/alignment projections shipped
this session.

## Non-goals

- Wiring any Ruby projection module into Vv::Graph::Sparql
  persistence — each gem will do that on its own follow-up slice
  if/when needed (144_7a vv-graph, 144_7b vv-memory, …).
- Updating Inventory's `paths_for` to skip Rust gems at P5
  evaluation. The polyglot fix obviates that need.
- Generating Turtle from the .md files; they're contract
  documents, not runtime artifacts.
