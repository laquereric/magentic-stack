# Row 114 — gate `main` on a green sweep

Measured 2026-09-03 from `77cd6cb`. **Built.** Owner decision
2026-09-03: refuse a push/merge to `main` unless the full checker +
plant sweep passes. Chosen over machine-readable hold state because
`cd1166a` was red and would have been caught regardless of who pushed.

This document records WHERE, WHAT, and the ESCAPE HATCH. The gate is
`bin/sweep`, `tooling/githooks/pre-push`, and
`.github/workflows/main-green.yml`.

## What actually happened (so the choice is not a wish)

`cd1166a` broke `check_boundary.py`. It was still ff-merged and pushed
to `origin/main` at 04:42:07. Main was red ~12 minutes until
`f3eb5eb`. A hold existed only in an a2a message. No tool could see it.
`mm-grok-land-tick` never merges. This repo lands by **direct push to
`main`**, not by GitHub PR.

CI that runs *after* the push would have gone red. Main would still
have accepted the bytes. That is the bug.

## WHERE: `core.hooksPath` is the refuse. CI is the net.

| | What | Catches `cd1166a`? | Cost |
|---|---|---|---|
| **A. CI only** (`on: push` to `main`) | Workflow runs `bin/sweep` after GitHub has the objects. | **No.** The red period *is* the incident. | Cheap. Already how release-gates work. **Insufficient.** |
| **B. CI on pull_request + required checks** | GitHub ruleset refuses a PR merge. | **No** for this land path. Agents push `main` directly. Rulesets are GitHub admin, not a file in this tree. | Would change the land path. Out of band. |
| **C. `core.hooksPath=tooling/githooks` pre-push** | Versioned hook. A push whose remote ref is `refs/heads/main` runs `bin/sweep` **before** objects are sent. | **Yes**, on any clone that has the hook installed. | `--no-verify` still exists (unrecorded). A clone that never ran `bin/install-hooks` has no hook. |
| **D. C + A** | Hook refuses the push. CI still runs on `main` so a `--no-verify` or a GitHub UI push is at least loud after the fact. | Yes on the land path; CI is the remainder. | **This is v1.** |

**v1 takes D.** The incident was a local push. Only a hook can refuse
it. CI cannot. A GitHub ruleset that forbids direct pushes to `main`
would be stronger and is **not this change** — it lives in GitHub
admin, and flipping it without the owner would lock the land path.

`bin/install-hooks` sets `core.hooksPath tooling/githooks`. The checker
fails if `.git` exists and `core.hooksPath` is not that path, so a
clone that never installed the hook cannot report a green sweep.

## WHAT it runs

`bin/sweep` discovers, then runs:

- `tooling/**/check_*.py`
- `tooling/**/plant_*.py`
- `tooling/**/plant_*.rb`  (gap 111: a `.py`-only find is the wrong population)

Zero jobs is a fail. A named exclusion that matches no file is a fail.
An exclusion must name a covering workflow that exists.

Named exclusion (one): `tooling/compose/check_role_routes.py` — boots
the mind-pod image per ROLE; covered by `role-routes.yml`. Everything
else runs on the host.

`LANG` is set to `en_US.UTF-8` if it is missing or not UTF-8
(`plant_two_writers.rb`). If a job cannot run — missing `rdflib`,
missing `ruby`, `ModuleNotFoundError`, non-zero, timeout — that is a
**FAIL**, not a skip. Absence of a toolchain is how a red landing
looks from the other side.

## ESCAPE HATCH (loud, recorded)

Git's `--no-verify` bypasses the hook and writes nothing. That remains
the nuclear option and is **not** the hatch.

The hatch is `MM_SWEEP_OVERRIDE=because:<reason>`.

- Empty, `1`, `true`, `yes`, or a reason shorter than 20 characters:
  **refused**.
- Reason must start with `because:`.
- The hook prints a banner to stderr (loud).
- It appends one JSON line to `$(git rev-parse --git-dir)/sweep-overrides.jsonl`
  with `at`, `sha`, `because`, `remote` (recorded on the machine that
  overrode; works in a worktree, where `.git` is a file).
- CI honours the same env; the banner is in the Actions log.

A green landing does not need the hatch. A red landing that uses it
is visible in the terminal and in the git-dir `sweep-overrides.jsonl`.

## Interpreter: repo-local venv, not host python3

The first push of this gate refused, correctly, because five jobs
`ModuleNotFoundError: rdflib`. Host `python3` is Homebrew 3.14, PEP-668
externally-managed, and `--break-system-packages` is forbidden.

`bin/sweep` prefers `.venv/bin/python` (path in
`tooling/governance/sweep.json`). Then:

| State | Meaning |
|---|---|
| **no venv provisioned** | setup. Host python also lacks rdflib. Run `bin/install-hooks`. |
| **venv present but incomplete** | rot. The venv exists and cannot `import rdflib`. Re-run `bin/install-hooks`. Do not fall through to host python. |

CI has no `.venv`; `setup-python` + `pip install -r tooling/shacl/requirements.txt` makes `sys.executable` capable, and that is the fallback only when no venv exists.

`bin/install-hooks` creates `.venv` with `python3 -m venv` and installs
`tooling/shacl/requirements.txt` into it. `.venv/` is gitignored.
