## 64. Unparsable is now reachable

Claude's row said the Hash guard can never fire. **Almost:** it *does*
fire for a YAML scalar or list. What it could not catch is the case
its `reason` names — `rescue -> {}` and `|| {}` both produce a Hash.

Three branches now:

| Input | Result |
|---|---|
| YAML that does not parse | `{ok:false, reason: :unparsable_frontmatter, because: {detail, class}}` |
| empty YAML (`nil`) | `{ok:true}` with empty fields — **no frontmatter fields**, not corrupt |
| parsed non-Hash | `{ok:false, reason: :frontmatter_not_a_mapping}` — new symbol |

`:unparsable_frontmatter` kept for the parse-error branch. The only
runtime reader is `Ingest#ingest_one`, which forwards `parsed` when
`ok` is false into `failed[]`. Nothing keys on the symbol beyond that.
Census U3 and the gap row are docs.

### What mounting SqliteIdempotency would require (not done)

PERSIST owns the path (rows 39, 43). A complete list, not a sketch:

1. A closed path in persist's set — not a free-form env string.
2. The sqlite file triple (`db`, `-wal`, `-shm`) on the volume BACK
   already mounts (`mind-data`). BACKJOB talks HTTP to BACK, so only
   BACK's process needs the store.
3. WAL already declared in `database.yml`; the idempotency sqlite is a
   **different file** and already sets `PRAGMA journal_mode=WAL` in
   its own `initialize`.
4. `sqlite3` gem (already a runtime dep of the app, not of rails-cpcp
   itself — the class `require`s it).
5. An initializer `ROLE=back` only: `RailsCpcp.idempotency_store =
   RailsCpcp::SqliteIdempotency.new(path: ...)`. FRONT/VAULT stay
   memory or none.
6. Create the parent directory; first-process `CREATE TABLE IF NOT
   EXISTS` (already in initialize).
7. Stop defaulting to `MemoryIdempotency` once the mount exists, or
   the in-process Hash still wins until assigned.
8. Acceptance: a PUSH, kill the BACK process, same `operationId`,
   replayed receipt — the incident the file comment already names.

Until persist names the path, do not invent one.
