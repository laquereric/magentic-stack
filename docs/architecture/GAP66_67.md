## 66. Which source was wrong

Two sources of truth about `shapes-level-8`:

| Source | What it said |
|---|---|
| `ProfileCatalog` | `L8 = "shapes-level-8"` defined, **never used**. All 16 `SHAPE_MAP` rows and the P9/P11 *operation* expansions resolve to `shapes-application`. |
| Binding manifest | 13 P11 protocol NodeShapes (`ConceptShape`, …) have `source_shape` = `gems/shapes-level-8/bundles/profile-11-meaning.ttl` and `execution: runtime`. |

The catalog's own comment is "Ownership from the binding manifest. Do
not re-decide here." So the **catalog** was the one that
misdescribed the system: the manifest already named those 13 as
runtime sources in L8, and the resolver ignored them.

P9 protocol shapes in the L8 bundle are **not** the same disagreement.
Their manifest `source_shape` is still the canonical file,
`execution: none`, `state: unowned`. Catalog not listing them agrees
with that. Left alone.

**Fix:** `L8_PROTOCOL_MAP` — 13 `P11::<local>` keys resolving to the
L8 bundle. `ProfileCatalog.default` merges it. `L8` is now a
resolution target. Gate: `check_catalog_manifest.py` — every
`execution=runtime` row whose source is under `shapes-level-8/` must
be a catalog hit on that file. Plant: rewrite `[L8,` to `[APP,`; the
gate fails.

Operation expansions still point at APP. Those files hold the
*operation* NodeShapes, disjoint names from the protocol bundle
(GAP23). Not a second design question.

## 67. Not comments-only — so we did not make the files identical

The brief said packaged vs legacy differ by comments on
`GovernedFieldsShape` / `SemanticDisputeShape`. **That is false of
P9.** `diff` of the protocol files:

P9 canonical vs L8 bundle:

- comment block above `GovernedFieldsShape` (legacy only)
- **`sh:ignoredProperties`**: legacy lists `rdf:type` plus the six
  governed fields; packaged lists `rdf:type` only. That is a
  **closed-shape semantic difference**, not a comment.
- extra comments elsewhere

P11: comment length on `SemanticDisputeShape`, plus
`EligibilityExplanationShape` moved to the end (constraints
unchanged).

Session-operations: already byte-identical.

**Refused:** ignore comments in the drift gate. A comment-insensitive
hash cannot be shown to still catch `sh:ignoredProperties` without
proving the stripper; that proof is the job, and we do not have it.
Making the files byte-identical would pick a side of the
ignoredProperties fork and hide it.

**Chose:** record the real delta and the live hashes in
`tooling/shacl/packaged_vs_legacy.json`. `check_packaged_legacy.py`
hashes both sides as whole files. A minCount change moves the digest
and FAILs. Updating the record is deliberate; stripping comments is
not an option the checker offers.

Plant: `sh:minCount 1` → `2` in the L8 P11 file; gate exit non-zero;
file restored.

## Why the other 67 answers lose

| Option | Why not |
|---|---|
| Strip comments in the drift hasher | Unproven against the ignoredProperties delta. Weakens a gate to silence a report. |
| Copy canonical → L8 | Silently adopts the six-field ignoredProperties list on the runtime pin. |
| Copy L8 → canonical | Silently drops that list from the canonical document, including the comment that says why it exists. |
| Record the classified hashes | Next person meets the mismatch at the checker, with the delta named. Real byte drift still fails. |
